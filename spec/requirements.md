# 总控台改造 Requirements

- 版本：2026-08-13-launch-flow
- 状态：用户已批准
- 最后更新：2026-08-13
- 唯一需求审批者：用户

## 1. 产品目标

让用户在 macOS Finder 中双击 `总控台.app` 后，无需打开终端即可启动或复用本地总控台服务，并自动打开完整 Web 控制页；项目源码同时归属于用户的 GitHub 仓库。

## 2. 范围

### 范围内

- 统一 `.app` 与 `start.command` 的启动行为。
- 启动或复用当前项目目录下的总控台实例。
- 等待健康接口确认 Web 服务可用后打开控制页。
- 启动失败时显示可读错误并保留日志。
- 将页面右上角 GitHub 图标指向 `https://github.com/jingking2005/local-ops`。
- 将本地 `origin` 连接到用户 GitHub 仓库，并把改造提交推送、合并到 `main`。

### 范围外

- 不通过源码绕过 macOS Gatekeeper。
- 不制作 Apple Developer ID 签名或公证包。
- 不改变总控台业务功能、数据模型或网络暴露边界。
- 不自动下单、不新增远程访问能力。

## 3. 用户与核心场景

| 用户 | 场景 | 成功结果 |
| --- | --- | --- |
| 当前 Mac 用户 | 双击 `总控台.app` | 浏览器打开总控台首页，页面可访问且服务持续运行 |
| 当前 Mac 用户 | 总控台已运行时再次双击 | 不重复启动服务，打开现有控制页 |
| 当前 Mac 用户 | 启动失败 | 看到系统提示，日志中有明确原因 |
| 项目维护者 | 点击页面右上角 GitHub 图标 | 打开用户自己的仓库 |

## 4. 正式需求

### CONSOLE-REQ-001 双击启动并打开控制页

- 状态：已批准，已批准待实现
- 用户价值：以 Finder 双击代替终端命令，直接进入可用控制台。
- 明确行为：`总控台.app` 启动后必须复用已有实例或启动服务，等待 `GET /api/health` 成功，再打开 `http://127.0.0.1:<port>/`。
- 验收条件：
  1. 在无总控台实例时启动一个服务并打开其首页。
  2. 在已有实例时不创建第二个实例并打开已有端口。
  3. 健康检查超时或启动异常时弹出错误提示，并记录 `console.log`。
  4. 不改变服务仅绑定回环地址的安全边界。
- 平台或角色差异：仅支持 macOS 12+；未签名 App 仍受系统首次授权规则约束。
- 范围外：Gatekeeper 签名、公证和跨 Mac 免授权分发。
- 来源与批准：用户 2026-08-13 明确确认改造方案。

### CONSOLE-REQ-002 GitHub 归属与链接

- 状态：已批准，已批准待实现
- 用户价值：源码、页面入口和本地 Git 历史统一归属于用户账号。
- 明确行为：页面 GitHub 图标指向用户仓库，本地 `origin` 使用用户仓库 URL。
- 验收条件：
  1. `git remote get-url origin` 返回 `https://github.com/jingking2005/local-ops.git`。
  2. 页面源码中 GitHub 链接为用户仓库，且无旧仓库链接。
  3. 改造提交存在于用户仓库 `main`。
- 来源与批准：用户 2026-08-13 明确指定仓库。

## 5. 非功能需求

- 安全与隐私：不提交 token、用户配置、日志或运行时数据；服务继续绑定 `127.0.0.1`。
- 可靠性：启动器必须等待健康接口，而不是固定 sleep 后盲目打开浏览器。
- 可观测性：失败原因写入 `~/Library/Logs/总控台/console.log`，用户看到简短错误提示。
- 兼容性：保留现有 `python3 server.py`、`start.command` 和服务端口 9600-9609 规则。
